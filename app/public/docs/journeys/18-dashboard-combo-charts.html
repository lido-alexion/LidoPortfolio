Dashboard layouts and stock combo charts

Existing main Dashboard personalization and Stock Details presets are live Investor workflows. Their frozen UX-003 and VIZ-001 boundaries apply here: bounded configuration, account ownership, known observations, one available account default, and explicit error recovery. These journeys qualify UI behavior; synthetic chart histories are not official market data or independent financial qualification.

E2E-49 — Customize the local Dashboard safely across devices

- Requires: An authenticated Investor and the main Dashboard.

- Warning: Local layouts belong to the current account and browser/device; another account's preferences must not be inherited.

1. Open the Dashboard (`/`) and inspect current portfolio values. Refresh recovery is E2E-14.

2. Choose Customize. Mandatory Portfolio Value, Invested Value, Total Gain/Loss and the portfolio summary card remain visible.

3. Choose Desktop or Mobile explicitly. Hide optional fields/cards, choose a supported card size and use accessible Up/Down moves. Desktop drag-and-drop is an additional move interaction.

4. Confirm changes in one variant preserve the other. Supported cards remain bounded and at least the mandatory summary remains visible.

5. Lock layout to prevent accidental edits and persist it locally. Reopen, Unlock and inspect the preserved variant.

6. Reset to defaults restores the unnamed local factory definition; it does not delete named dashboards or another account's layout.

**Expected result:** Account-local, independently configured variants preserve core data visibility and usable keyboard/touch controls.

E2E-50 — Maintain named dashboards and portable configuration with recovery

- Requires: An authenticated account with its own main Dashboard and reviewed layout definition.

- Warning: Imported/exported layout JSON is configuration only. An unconfirmed server write is not a confirmed import/save/delete; inspect and deliberately retry. JSON import always creates a new named layout.

1. Open the Dashboard (`/`). Existing local working preferences take precedence over an account default. An unavailable named list offers Retry without replacing the current local definition.

2. Save as named dashboard with an explicit name. Failed creation leaves the existing list and local working layout intact; inspect and repeat deliberately.

3. Select a named layout. Edit its variant and inspect Saving, Saved or Failed. Failed autosave keeps the reviewed local definition; Retry named dashboard save submits that exact current definition. If another device saves while a request is in flight, the response must not advance this device past the exact revision it saved; the next write conflicts safely and preserves both the local draft and newer server definition. If the server reports that another device changed the layout, reload the page and explicitly select that named dashboard to load its latest server definition before editing again. Changing layout/account does not silently retry the rejected write.

4. Set one account default. A failed update retains the prior indication. Correct/retry explicitly and verify the confirmed default.

5. Rename or Duplicate a named dashboard. On failure, the original record remains intact. Duplication creates a separate record; it never replaces a sibling.

6. Copy a selected named dashboard to this device to detach the unnamed local working layout. Reopening preserves local precedence.

7. Delete only after confirmation. Cancellation produces no delete request; a rejected deletion retains the record for deliberate recovery.

8. Import a JSON file within 32 KB. Invalid syntax/size fails before persistence. Compatible fields/card preferences survive; unsupported entries are skipped with a warning and mandatory core visibility is restored.

9. A service failure after a valid import is identified as an unconfirmed import, rather than invalid JSON. The original file remains unchanged and can be reselected for deliberate retry.

10. Export JSON and inspect schema/version, lock and both variants. It contains no account identifiers, holdings, portfolio values or live data. Data export jobs and basket recovery are separately E2E-18/19.

**Expected result:** Named records are account-owned, default/lifecycle changes are confirmed, and portable definitions preserve financial data boundaries.

E2E-51 — Explore stock combo presets and recover saved defaults

- Requires: Authenticated Stock Details with canonical dated price and metric observations available for supported presets.

- Warning: Insufficient or unavailable history disables the affected preset with a reason. No fabricated observations, fundamental forward filling, provider synchronization or training is authorized by a chart retry.

1. Open Stock Details (`/watchlist/TCS`). Existing Price + Volume and individual analytical charts remain available; only one combo preset is active.

2. Inspect the grouped preset selector. Once the account preference and its history availability are resolved, an available explicit default wins; otherwise use Price + Volume, then the first available preset. While a saved metric default is still loading, the chart may show actual Price + Volume observations with an explicit pending status; the pending default cannot be mistaken for an unavailable metric or overwritten by saving the temporary fallback. A failed saved-preference read is disclosed and is not labelled as a known saved default.

3. Other metric histories settle independently. Pending presets remain visible and disabled with a loading reason; rejected reads receive a temporary-unavailability reason, and successful reads become selectable only after coverage rules pass. Retry an unavailable account preference or historical read explicitly. These issue ordinary read requests only.

4. Select a preset or use Previous/Next with cyclic wrapping, skipping unavailable entries. No arbitrary metric combination, favorites or custom axes are offered.

5. Temporarily show/hide visible series using named legend controls. Inspect range and Daily/Monthly/Quarterly sampling inside the chart. Fundamental values remain on their dated observations, with preserved units/dual axes and aligned visible-series tooltips.

6. Choose Set as default deliberately. A failed write retains the selected chart and explains the failure; retry then verify the confirmed account default. A new Stock Details open honors it across devices once its history availability resolves; a deliberate chart choice made during loading remains selected for that open, while temporary legend/range choices do not override the saved default.

7. Use keyboard/touch controls and inspect unavailable reasons; targeted full WCAG checks cover the combo chart. Source/calendar cadence and actual backend persistence remain independent domain contracts.

**Expected result:** Preset controls, availability and defaults remain coherent without rewriting canonical financial observations.
