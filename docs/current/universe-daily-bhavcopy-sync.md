# Daily universe exchange-file collection

Product Owner source-policy amendment, 25 October 2026, tracked in [defect #280](https://github.com/lido-alexion/LidoPortfolio/issues/280).

Daily universe OHLCV collection uses the official NSE CM UDiFF final ZIP and the existing BSE bhavcopy downloader. The full canonical active NSE + BSE-only equity scope is inspected on every daily run; the historical stock batch-size setting does not restrict it. Each exchange/session file is downloaded once and matched across that exchange's eligible stocks.

Operational health follows validated exchange-file evidence, separately from stock-row coverage. A newly downloaded and validated file, or a still-valid cached receipt for the same scope and coverage fingerprint, is healthy source evidence even when official rows are absent for some or all individual stocks. Those missing bars remain visible as partial/unavailable coverage in universe diagnostics and are never fabricated. A run with no recent download and no valid receipt is not healthy by inference. Identity conflicts, missing validated source evidence on an unsuccessful run, and persistent failed or retry-deferred exchange-file sessions remain visible even when `file_errors` is zero or the universe run is partial. A first transient file failure can remain quiet while its retry window is pending; repeated attempts escalate. Retry/backoff and the existing bounded session lookback continue to apply. Historical coverage counts such as 574 unavailable stocks are not by themselves proof of a regression: compare source evidence, identity conflicts, retry state, and the matched run outcome. `stox:check-data-completeness` continues to alert for other incomplete readiness datasets and forward-data conditions. It suppresses a daily-price-only alert only when the enabled daily collector has complete validated receipts including the current required NSE session, a matching finished partial/failed `SyncRun`, and at least some rows in that required session; absent required-session rows remain actionable.

Each expected stock/exchange session also has a durable outcome in `portfolio_universe_price_session_outcomes`: `covered`, `no_data`, `skipped`, `not_expected`, `provider_error`, `systemic_error`, or `ignored`, plus a separate `price_present` flag. Session-date and cooldown calculations use the NSE/BSE market timezone (`Asia/Kolkata`) even though the application clock is UTC. A source failure remains visible even when an older price row is already cached; that cached bar is never deleted or relabeled as current source success. Absence from a validated exchange file with no bar is `no_data`, not a provider failure, and does not create an operational notification. A session before the security entered the stock master is recorded as `not_expected` for this ledger, without changing historical gap detection. This is not proof of the actual listing date. A failed download is a provider error; invalid identity/schema, a missing expected file record, or persistence failure is systemic. Replays upsert the same stock/session row rather than inflating observations. Outcome rows are retained for 120 calendar days. `portfolio_universe_price_symbol_states` stores consecutive no-data sessions and the temporary reprobe window; five consecutive valid no-data sessions start a five-market-session cooldown. The first reprobe is on the following eligible session, after those five sessions have been skipped. Admin can reset that cooldown to be checked on the next daily run; resets are audited in `portfolio_universe_price_admin_events`.

The per-stock no-data cooldown describes observation policy only. Daily acquisition still reads one exchange file for the full eligible scope; it does not add a per-stock Yahoo fallback or fabricate zero bars. Sessions during cooldown remain `skipped` observations; the exchange file is still checked, so a newly returned bar immediately resolves the gap. No-data never fills a historical gap, satisfies freshness, or grants Strategy/ML/trading eligibility. Only a later verified persisted bar resolves that session as covered; the resolver records the historical provider source. Existing history scans and explicit backfill continue to report and repair genuinely missing trading-session bars. Weekends and active trade holidays are not expected sessions.

File retries use four attempts per recovery window with delays of 5 minutes, 15 minutes, and 1 hour between the first three failed attempts. After the fourth failure, automatic reprobe waits five equity sessions and follows the active StoX holiday calendar; a known changed source revision can retry immediately. Repeat alerts are restricted to source/identity failures or a sustained breadth collapse. A collapse alert requires at least two consecutive sessions with 80% or more no-data outcomes for the same exchange after at least five baseline sessions averaging 40% or less; it remains active until two consecutive healthier sessions. Existing operational-alert deduplication and recovery routing apply. Normal no-data outcomes, temporary skips, and retry-pending file failures do not page administrators.

Coverage-only suppression requires the run's persisted `bulk.expected_files` workset to match its complete successful `bulk.files` evidence one-to-one by exchange and session date. The collector records the exact exchange set and bounded date range; the alert evaluator independently reconstructs the complete expected workset using `TradingCalendar` before accepting the persisted list. Weekends and active trade holidays produce no expected file. Each receipt must include a valid source revision hash, coverage fingerprint, and check timestamp. Missing/legacy expectation metadata, a missing exchange/session file, duplicate or unexpected files, malformed receipt provenance, or a stats/SyncRun completion mismatch cannot establish source health. This is intentionally fail-closed because older records do not prove the complete source workset. Quieting a first transient failure has a separate strict proof: exactly one represented `exchange_fetch` failure at retry attempt 1, all other expected files have valid receipts, the matching finished `SyncRun` is failed/partial and within five minutes of completion, and the run error list contains only the exact file error plus known row-coverage diagnostics corroborated by bounded stock samples. Identity validation, persistence, repeated, ambiguous, or uncorrelated failures remain actionable.

The recent recovery window remains bounded by the daily lookback configuration, with a hard limit of 31 calendar days. Weekends and active global trading holidays in the StoX calendar never generate file requests or price rows. A weekend or holiday maintenance retry can recover earlier valid sessions when the prior equity-session run has actionable failure evidence. A partial or failed coverage status remains visible for readiness; it does not by itself trigger that retry when the matching run log proves complete, validated receipts for every expected exchange/session file, zero file or identity errors, and that all failed stocks are accounted for by unavailable coverage. Missing or malformed run evidence remains retryable. This does not change the bounded per-file retry/backoff policy or coverage readiness. This amendment changes the daily universe source policy; frozen archived specifications remain unchanged.

## Validation and persistence

- NSE archives must contain one correctly dated CSV within bounded archive and CSV sizes. Every row must have the requested trade date, exchange, and CM segment. Only stock rows from the final session are eligible.
- Schema, finite positive OHLC values, consistent high/low bounds, nonnegative integer volume, and stock identities are validated. NSE matching uses symbol/series or an unambiguous ISIN/series; BSE uses scrip code or an unambiguous ISIN. Conflicting identities are rejected. Absence from a file is not evidence of delisting or a fabricated no-trade bar.
- Daily writes insert missing stock/session rows atomically. Existing cached prices, corporate-action adjustments, and manual repairs are preserved.
- A compact receipt records validated file application and actual coverage. Stable membership and unchanged coverage reuse it; membership/identity/ignored-gap changes, removed price rows, or an explicit daily reset request trigger a fresh check. Receipts are pruned to the bounded recovery window. Raw files and price arrays are not stored in settings.
- Coverage classification continues through the existing missing-history owner, including its listing-prefix, gap-tolerance, and ignored-gap rules. Scope completion is distinct from complete price coverage. File failures, identity conflicts, and required unavailable history remain visible in sync logs and last-run diagnostics.

A stale or legacy overlapping proof aborts before price or ledger mutation. A later action composes with earlier adjustments and refreshes the earlier proof; a second completed factor for the same stock/ex-date is refused to prevent duplicate application. `PriceFetchService` skips the configured pre-action interval, while diagnostics and repair retain access to raw physical evidence. The fingerprint query loads only the configured stock's affected history and makes one ordered read per evidence check; this trades some repeated work for fail-closed content validation. ## Owner boundaries

Daily universe collection has no silent Yahoo/Alpha Vantage fallback. Scheduled maintenance does not immediately follow it with the old per-stock gap-fill or extra retry loop. Explicit historical, history-depth, and manual gap backfills retain their existing providers and resumable stock cursor. Daily bulk runs preserve an unfinished historical cursor.

The held-portfolio daily job, benchmark and index jobs, dataset freshness ledger, scheduling window, and alert ownership remain separate. This change does not assert that those other owners never use a per-stock provider. Existing settings enablement and in-progress handling are retained, with a database cache lock preventing concurrent universe writers.
