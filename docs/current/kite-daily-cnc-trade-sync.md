# Kite daily CNC trade sync and reconciliation

StoX imports executed NSE/BSE equity trades with Kite product `CNC`. MIS, NRML, MTF, derivatives, and other products are excluded. Each fill is written through `TransactionWriteService`, so the configured transaction fee engine, holdings calculation, realizations and cash ledger are applied. The unique profile/trade-ID key makes repeated retrieval idempotent. Trade ID, order ID, execution timestamp, exchange, product and broker evidence remain in `kite_cnc_trade_imports`.

Kite's Trades API supplies the current trading day's tradebook. The scheduled sync runs after the configured market close plus reconciliation delay (30 minutes by default), and reconnect performs current-day catch-up immediately. The manual Sync CNC trades action is also available. A later session is not represented as successfully recovered when the broker API can no longer retrieve it: a gap is persisted and exposed for review.

Existing transactions are matched by stock, side and trade date. An unambiguous one-to-one match links individual partial fills to individual ledger rows; a single exact aggregate ledger row can also represent multiple broker fills using aggregate quantity and weighted execution price. Duplicate or split candidates without a unique mapping are retained in `manual_match_review` and are not imported a second time. Missing instrument mappings and invalid CNC rows are reported in sync counts. Sell fills that cannot be safely attributed to an owner are not guessed.

Reconciliation compares the current StoX ledger with Kite holdings. Kite `quantity`, `t1_quantity` and `used_quantity` are normalized. Recent imported or matched CNC executions are grouped across unsettled equity sessions, using the trading calendar. A settlement adjustment is applied only if its complete net quantity exactly explains the StoX/Kite difference; partial or ambiguous reflection stays a discrepancy. Broker positions are retained as raw evidence and are not added to holdings, because they include MIS/NRML and other non-delivery products. Missing holdings, positions, funds or tradebook evidence fails the run instead of producing a clean comparison.

The holdings/funds reconciliation runs after trade sync near 16:00 IST and can be triggered manually with one Reconcile action. It always includes the current StoX ledger, current-day CNC executions and execution-proven unsettled adjustments; the legacy `ignore_today_transactions` request field is accepted for compatibility but no longer selects a previous-day comparison. Live execution also requires one successful holdings/funds baseline per equity session. Before every BUY, StoX obtains fresh Kite buying power and subtracts account-wide pending buy reservations and estimated fees. Before every SELL, it obtains current sellable holdings and subtracts account-wide pending sell quantities. Unknown/partial broker order states across the account prevent another order until reconciled. Confirmed fill deltas are recorded once; full portfolio reconciliation does not run after each order fill.

The current Kite funds endpoint reports available equity buying power, not a comparable settlement cash ledger. The official `/user/margins/equity` response includes `available.cash`, `available.opening_balance`, `available.live_balance`, `available.intraday_payin`, `utilised.debits`, and `utilised.payout`. `net` is explicitly a trading balance derived from intraday pay-in, adhoc margin, and collateral; `live_balance` reflects margin use. None is a complete dated cash ledger that can be reconciled to StoX's accounting balance after CNC trade flows, charges, all pay-ins/payouts, and other broker cash adjustments. Reconciliation therefore retains the reported amount and its `available_equity_buying_power` basis as evidence but marks funds `unknown`; a numerical match does not pass the session baseline. Per-order fresh buying-power checks remain mandatory.

Until a comparable machine-readable ledger source exists, the safe manual evidence path is a same-session Zerodha Console ledger/funds statement reviewed by an authorized operator against StoX's cash ledger from the last reconciled point through that statement's cutoff. The review must account for every pay-in/payout, CNC buy/sell cash movement and fee, and any other broker cash entry; document the statement date/cutoff and the signed unexplained residual; and resolve open or uncertain broker orders. Missing coverage, unclassified entries, a stale cutoff, or any unexplained residual keeps the baseline blocked. Such manual evidence is for review and accounting correction through normal StoX workflows; it does not permit bypassing the existing baseline gate or substitute for a validated automated source. No session baseline can pass on funds API values alone today.
