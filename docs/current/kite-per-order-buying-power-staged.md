# Kite per-order buying-power gate — staged implementation

The `KITE_PER_ORDER_BUYING_POWER_GATE_ENABLED` setting defaults to `false`. In this state, Kite submission behavior is unchanged. If enabled, the live Kite order path evaluates each buy through `KitePerOrderBuyingPowerPolicy`; unsupported order type, invalid/missing limit, wrong account, stale/missing/error evidence, or inadequate buying power fails closed. Sells do not require buy-power evidence.

The pure evaluator supports calculating a candidate bounded LIMIT order: gross required funds are quantity × limit price, plus a configurable percentage charge buffer (default 5%). That calculation is not an approved live margin model. The current order path submits MARKET orders, and no frozen policy authorizes changing those orders to LIMIT; enabling the gate therefore blocks Kite buys with `unsupported_order_type`.

Evidence is explicitly tagged `broker_equity_buying_power_not_stox_accounting_cash`. Kite equity buying power is broker capacity and must never be treated as StoX accounting cash or proof of ledger reconciliation. The evaluator also requires verified response account identity, provider timestamp, and order-margin provenance before it can authorize a hypothetical LIMIT buy. The existing scalar funds adapter supplies none of these proof markers, so it cannot authorize a buy even if order type handling changes. These checks fail closed and are unit tested. Sells bypass the buy-power check. This feature does not change the shadow session-evidence gate or its fail-closed baseline requirement.

The existing gateway's `availableEquityFunds()` returns only a scalar and erases provider errors/timestamps. A local request-completion timestamp and local Kite connection ID do not prove provider response age or identity in the response. Before enabling production enforcement, replace this adapter evidence with typed, account-bound Kite evidence; establish defensible freshness (or retain a permanent fail-closed result when it cannot be proven); validate available-equity field semantics; and use a broker order-margin/charges calculation proven against the relevant product/order and open-order reservations. Define an explicit scoped order-type and price-bound policy before allowing any non-MARKET submission. The limit price must be demonstrably tied to a current quote and never exceed the authorized bound. Reconnection must invalidate prior evidence. Keep this feature flag disabled until these items, API failure behavior, retry/idempotency controls and the existing broker kill-switch/session baseline have passed independent safety review.

There is currently no live usable per-order BUY path from this staged work: MARKET orders remain unchanged and fail the candidate evaluator, and hypothetical LIMIT orders lack verified provider evidence and approved price semantics. No silent order conversion is permitted. Existing submission-key / active-order checks remain the order identity and retry controls; a blocked affordability check occurs after that claim, so retries return the same active order rather than creating another broker submission. This staged check does not alter StoX cash accounting or session baseline accounting.

Reference: [Kite funds and margins](https://kite.trade/docs/connect/v3/user/) and [Kite order margin calculation](https://kite.trade/docs/connect/v3/margins/). Kite documents the order-margin endpoint as considering existing positions and open orders; StoX does not yet consume that endpoint in this staged increment.
