# Kite current account evidence capture

`php artisan stox:kite-current-account-evidence USER_ID` performs a bounded, read-only operator capture using the stored usable Kite session for that user. It calls only the official HTTPS `api.kite.trade` endpoints `GET /user/profile`, `GET /portfolio/holdings`, and `GET /portfolio/positions`, with redirects disabled. The profile identity is checked before and after the portfolio reads against the caller-selected stored `broker_user_id`; owner, connection, account, token and valid session timestamps must match at the initial, intermediate and final checks. Observations exceeding 35 seconds or with a reversed wall-clock interval are rejected. The command fails closed on request/status/shape/identity/session errors.

Output contains only pass/fail, UTC observation timestamps, bounded elapsed duration and row counts, explicit `empty` versus `observed` states, and fixed scope labels. It does not print account identifiers, holdings/position rows, prices, balances, credentials, or provider error text. The in-memory broker payload is discarded after deriving metadata; no database rows are written. A restricted local review copy of raw rows could help a human inspect the observed securities, but it materially increases financial-data exposure and retention risk, so this command does not create one.

This observes the account's current holdings and both positions buckets only. It is not historical coverage, a broker statement, settlement/payout/margin verification, reconciliation, or acceptance evidence, and it triggers no automatic action. The settlement comparator still needs separately sourced, account-scoped historical CNC trade coverage and independently verifiable settlement or statement evidence before stronger claims are possible.
