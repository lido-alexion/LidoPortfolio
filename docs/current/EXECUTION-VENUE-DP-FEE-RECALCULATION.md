# Execution venue and Zerodha DP fees

Each transaction stores `execution_exchange` independently from the stock master exchange. Legacy rows are initialized to NSE by the forward migration, including historically BSE executed rows; operators must correct known venue history before relying on historical recalculation. Zerodha DP component is ₹13 fixed plus 18% GST (₹15.34), sell only. It is a separately billed depository charge and is not part of contract note charges unless a broker statement explicitly confirms that treatment.

DP grouping uses portfolio/account, ISIN, and transaction date. The current persisted owner is the newest eligible sell row in that group; a marker on that row records the ₹15.34 allocation. Create, edit, and delete reallocate the marker under the portfolio row lock and post signed cash-ledger adjustments for any fee moved between surviving rows. Repeating reconciliation is idempotent. Bulk preflight includes one DP charge only when no existing marked charge exists for that group, and it runs under the same portfolio lock as the writes.

Historical rows are explicitly dp_policy_enrolled=false after migration (regardless of when originally entered); only new, cash-backed, non-simulation writes opt in. No pre-deployment transaction acquires DP just because its created_at happens to be recent. An ordinary edit to a legacy row retains its stored fee amount; it does not run historical fee recalculation. Cashless writes and simulation/replay rows do not acquire DP fees. Cashless edits or deletes of rows already represented in the cash ledger fail closed because they cannot safely reconcile the cash ledger. Simulation provenance is accepted only in Paper portfolios.

The transaction schema does not record settlement type, so auctions, T1, and other separately billed settlements cannot be distinguished. Those cases require statement-backed manual review; the tool reports missing ISINs as blockers and does not fabricate group keys. STT rounds to the nearest rupee. Brokerage minimums are not synthesized because current fee settings do not encode contract-note aggregation rules.

Run `php artisan portfolio:recalculate-transaction-fees --output=/secure/operator/path/report.json` for a dry-run. This command is strictly report-only: it has no apply option and cannot update fees, venues, cash entries, balances, or snapshots. Historical fee recalculation and any cash adjustment are deferred to a separate owner-guided phase. The report includes row fees, DP group keys, cash deltas, fee-only realized P/L estimates, and blockers. Do not treat a report as confirmation that the broker separately charged DP; compare contract notes and funds ledger first.
