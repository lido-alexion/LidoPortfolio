## Method and Authority Notes

- `docs/current/README.md` says `docs/current/**` is the current source of truth and archived specs are for historical context/source archaeology.
- This audit therefore records `docs/current/**` as the current representation, but does **not** assume that omission from `docs/current` proves an older accepted requirement was intentionally superseded.
- Requirement rows are captured at feature/epic level with meaningful acceptance criteria. Some historical specs contain many individual `SHALL` statements; those are grouped when they belong to one committed feature contract.
- Implementation is **not** inferred from filenames, test names, or similar-looking components. When implementation evidence is mentioned, it is treated as a Phase 2 inspection target, not a Phase 1 completeness finding.

## Potentially Lost Requirements

1. **Page Visit History / right-edge rail**  
   Origin: `docs/archive/specs/V6-E4-Investor-UX-Client-Evolution.md` lines 181-194 and 394-414. It specifies a desktop right-edge vertical rail with last 12 visits, duplicate collapse, active state, hover/focus label reveal, link entries, and a mobile History action. Current `docs/current/frontend-and-navigation.md` lines 1-80 does not represent it.

2. **Global shell right utility rail/pane architecture**  
   Origin: V6 E4 lines 83-107 and 181-194. Current frontend docs describe sidebar taxonomy and PageChrome but omit the five-zone shell and right utility rail.

3. **Contextual Notes shell placement**  
   Origin: V6 E4 lines 418-430 and V6 wishlist lines 116-120. Current Knowledge docs cover Knowledge Board notes, but not the cross-page contextual note rail/pane contract.

4. **V6 E4 non-regression inventory gate**  
   Origin: V6 E4 lines 25-79. Current docs do not require before/after capability inventories for redesigned pages, despite this being acceptance-critical for fit-and-finish work.

5. **Standard page anatomy/component contract**  
   Origin: V6 E4 lines 155-219, 261-283, 560-575, 735-743. Current docs do not preserve breadcrumbs/page headers/tabs/segmented controls/drawers/skeletons/scroll-to-top/PageHistoryRail as a product UX contract.

## Contradictions or Tensions

1. **Current source-of-truth condensation vs V6 E4 accepted UX detail**  
   `docs/current/README.md` says current docs are the source of truth, but `frontend-and-navigation.md` omits accepted V6 E4 shell, page history, contextual utility rail, non-regression, and component requirements. This looks like documentation consolidation loss unless a superseding decision exists.

2. **V7 namespace goal vs legacy-name preservation**  
   V7 namespace specification wants canonical `stox_` ownership for StoX DB objects, but V7 register explicitly limits current enforcement to new V7 objects and current docs still acknowledge legacy `portfolio_*` names. This is not necessarily a contradiction; it is a partial/split requirement that must not be treated as fully complete.

3. **Deployment verification state**  
   V5-FEAT-031 and V5-FEAT-042 are implemented but have production verification/ownership audit gates still pending in archived specs. If the deployed application is treated as “complete through V7,” Phase 2 should verify whether those gates were later satisfied outside the captured current docs.

4. **Accepted feature detail vs current domain summaries**  
   Many current docs summarize entire domains in broad prose. That is workable for a product overview but loses fine-grained acceptance criteria for UI behavior, non-goals, filters/sorting constraints, retry semantics, and audit evidence. This is most acute for frontend/navigation, notifications, execution, and artifact framework details.

## Specific Origin of Page-History / Right-Edge-Rail Requirement

The requirement originates in **V6 E4 - Investor UX & Client Evolution**, not in V5 or V7.

- The V6 register marks E4 complete and states it covers `V4-FEAT-043`, `V4-FEAT-016`, and `V4-FEAT-035` (`docs/archive/specs/LidoPortfolio-V6-Wishlist.md` lines 95-108).
- E4 defines the shell zone: **Right Utility Rail / Contextual Pane - page history, Notes and future contextual utilities** (`docs/archive/specs/V6-E4-Investor-UX-Client-Evolution.md` lines 101-107).
- E4 states initial utilities are **Page Visit History** and **Contextual Notes** (`lines 181-187`).
- E4 component placement table states **Page history = Right-edge rail; mobile History action** (`lines 261-278`).
- E4 §8 gives the concrete Page Visit History acceptance details: right-edge vertical rail, last 12 visits, duplicate collapse, active state, bars, hover/focus labels, and mobile sheet/drawer (`lines 394-414`).
